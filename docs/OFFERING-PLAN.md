# Offering dan konversi pegawai

Ruang lingkup disetujui: HR mencatat penawaran, mengunduh ringkasan PDF internal, mencatat respons dengan bukti PDF privat, lalu mengonversi kandidat diterima ke pegawai tanpa mengetik ulang identitas. Tidak mengirim penawaran/email baru, tidak tanda tangan elektronik, tidak menyusun kontrak hukum.

Penawaran per lamaran: departemen/jabatan, status kerja, tanggal mulai, batas respons, catatan ketentuan opsional. Tanpa nominal gaji khusus/payroll. Satu penawaran dapat diperbarui sebelum respons; setiap pembuatan/perubahan/respons menyimpan audit snapshot actor/waktu UTC. Update memakai application.version dan row lock; setelah respons tidak bisa diubah. Pilihan respons: menerima, menolak, ditarik HR; alasan minimal10karakter dan bukti PDF maksimal5MiB wajib. Penerimaan mengubah Offering→Diterima; respons lain→Ditolak secara atomik. Perubahan tahap Diterima lewat endpoint lama harus memerlukan penawaran diterima. Setelah penawaran dibuat, keputusan akhirnya dicatat melalui respons agar tidak melewati bukti.

Admin/Staf HR saja dapat mengelola/membaca penawaran, bukti, ringkasan dan konversi; Viewer tidak menerima terms/audit/file. PDF berlabel ringkasan internal, bukan surat resmi/kontrak; remote/PHP/JS Dompdf dimatikan. File respons memakai disk privat employee_records pada direktori offer-responses terpisah; unduh melalui otorisasi dan relasi lamaran, tidak lewat URL publik. Rollback menghapus file.

Konversi: hanya lamaran Diterima dengan penawaran diterima dan email publik terverifikasi. Lock aplikasi lalu profil; cek employees termasuk arsip; unique applicant_id dan source_application_id mencegah ganda lintas lamaran. HR mengonfirmasi identitas, mengisi nomor/email kerja, boleh mengoreksi nama/telepon hasil prefill; departemen/jabatan/status/tanggal mulai berasal dari penawaran. EmployeeRecords::save dipakai agar validasi/pencatatan audit pegawai tetap berlaku. Seluruh proses transaksi; klik ulang tidak membuat pegawai baru. Tidak membuat akun login, menyalin CV ke ruang publik, memulihkan/menimpa pegawai lama, atau menghapus kandidat.

Validasi dan tes: RED sebelum endpoint/migration, GREEN untuk revisi/audit, bukti/transaksi, status/email/role, department-position, duplicate/archived dan journey publik sampai pegawai. Migration additive tanpa reset development; semua gate AGENTS; review terpisah dan browser desktop/mobile. Tidak push/deploy.
